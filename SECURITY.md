# Security policy

## Reporting

Do not disclose a suspected vulnerability, credential, or personal data in a public issue. Contact the repository maintainer privately through GitHub (`@karkalashivareddy`) with a concise report, reproduction steps, affected commit/version, impact, and safe evidence. Do not include live secrets or exploit another system. This repository does not currently publish a formal response-time SLA or a private vulnerability-reporting endpoint; coordinate course/team escalation as appropriate.

## Scope and safe testing

Only test local instances and resources you own or have explicit authorization to assess. No production cloud environment is claimed to exist. Never run destructive recovery, denial-of-service, credential stuffing, or third-party attacks. See `docs/05-security/` for design baseline. No certification or compliance claim is made.
